# UIサイズの調整箇所

実機とブラウザの表示差は、端末の viewport・pixel ratio・safe area によって発生します。まず同じ向き、同じ viewport サイズで比較してください。

## 共通ボタン

共通のモーダルボタンは `css/modals.css` の以下を調整します。

- `.primary-btn`: 主要ボタンの `padding`、文字サイズ、角丸
- `.action-btn`: 通常の操作ボタン
- `.btn-secondary`: 補助ボタン
- `.btn-sm`: 小型ボタン

画面や端末ごとに変える場合は、共通値を直接変更せず、`css/responsive-scrollfree.css` または対象画面のCSSでメディアクエリを追加します。例えば横画面の更新通知ボタンは `.update-confirm-btn`、フィードバック送信ボタンは `#feedback-modal .primary-btn` です。

## 実機差の確認

ブラウザの開発者ツールで端末プリセットを選び、次の値を揃えて確認します。

```text
viewport width / height
device pixel ratio
portrait / landscape
ブラウザのアドレスバー表示状態
```

実機ではアドレスバーやsafe areaの影響で高さが変わるため、固定pxを増やすより `max-height`、`dvh`、既存の `data-is-compact` 用ルールを優先してください。

## 横持ちホーム・コース選択の比率配置

`index.html` が取得した実表示領域を `--app-width` / `--app-height` として使用します。SafariのブラウザUIで高さが変化した場合も、`#app` とロビーの基準を同じにします。

横持ちのコンパクト表示では、ヘッダーを除く残りを `main` に割り当て、左右の列は既存の `1.15fr : 1fr` を維持します。ホームのソロ・マルチのモードカードは概ね `1 : 1`、車体プレビューとコースプレビューは残りの領域へ伸縮します。文字・操作ボタンに最低サイズを残し、コース選択の車体情報カードは必要な場合だけ内部スクロールします。端末名による分岐や画面全体の画像的な縮小は行いません。

`tests/mobile_lobby.cjs` は横持ちiPhone 16・Pixel 9相当サイズと表示高さ縮小時のホーム／シングルの主要ボタン到達性を確認します。実機Safariの検証とは区別してください。

## 横画面起動とOSの入力UI

起動時の縦横選択を廃止し、横画面レイアウトを既定にします。開始タップで、対応するブラウザには全画面化の完了後に `screen.orientation.lock('landscape')` を要求します。manifestにも `orientation: landscape` を指定します。

iPhone 16 / iOS 26.4.2 の実機ホーム画面起動では、Web Inspectorから `screen.orientation.lock` とHTML要素の `requestFullscreen` がどちらも `undefined` であることを確認しました。この環境でCSS回転はゲームの見た目を横にしますが、OSの画面向きは固定できません。縦向きのOS上で開いたキーボード・ファイル選択をCSSで回転させることもできません。OS UIまで常に横に固定することが必須なら、横向きのみを許可したiOSネイティブのWebViewアプリ等が別途必要です。manifestの指定だけでiOSの対応を保証しないでください。

通常の横持ちと、縦向きOS上でゲームだけがCSS回転している状態を区別して検証します。#59の開始ボタン欠けは後者で再現したため、コンパクト用の高さ配分をCSS回転時にも適用する回帰検証を追加しています。

実機画面取得は既存のLocal_LLM_by_using_MobilePhoneプロジェクトと同じ `pymobiledevice3` のCoreDevice方式を使います。ホストの依存環境は変えず、Docker内でDDIの準備後、`developer core-device screen-capture screenshot` で取得しました。古い `idevicescreenshot` の失敗だけで、デベロッパモードや信頼設定の不足と判断しないでください。iOS 26.4.2でCoreDeviceのHIDによる遠隔タップはiOS 27以降が必要とのエラーになりましたが、Web InspectorによるゲームDOMの確認・操作は可能です。

## モーダルと公開フィードバック

#60・#61で報告された設定・リザルト画面は、CSS回転時にも `#app` を基準に配置し、カードの最大高さを親領域の100%に制限します。ヘッダー・終了操作は縮めず、内容だけを内部スクロールします。縦のOS上での `vh` / `vw` を、回転後のカード寸法として使わないでください。

画像は5枚まで、選択時は1枚2MBまでです。追加選択と右上の×による削除に対応し、送信前に最大1600px・JPEG約180KB以下へ再描画して元のEXIFを持ち越しません。送信失敗時は本文と選択画像を保持します。APIは旧フォームの単一画像も受理し、全画像を保存してからIssueを作成します。

公開する動作情報は、アプリ版・配信コミット、ブラウザ/OSの種類と申告主バージョン、画面分類、ソロ/マルチの区別、標準コースIDまたはcustom、操作/画質設定、表示領域・DPR・safe area、CSS回転/全画面/ホーム画面起動/向き固定APIの有無、自動アクセルです。フォームを開いた時点の値を採り、送信側とAPIの双方で許可リストに限定します。URL・クエリ・ルームID・UA全文・IP・通信ログ・保存データ・カスタムコース名・元ファイル名は自動掲載しません。任意のお名前・再現手順・本文・画像はユーザーが入力する公開情報であり、フォームでその旨を明示します。

Chromeの端末エミュレーションは解像度等の近似確認に使います。Safariの描画、ブラウザUIやキーボードによる領域変化、PWA起動、OSの回転・ファイル選択は実機で別途確認してください。
