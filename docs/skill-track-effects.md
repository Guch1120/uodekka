# 固有スキルの痕跡・スキル回復ゲート

## 採用した動作

走行中に選択画面や配置ボタンを増やさず、固有スキルを発動した路面位置に加速の痕跡を残す。所有者・後続・CPUが同じ痕跡を使える。利用回数による消費はなく、板を抜けたときに短い加速が発動する。空中・復帰中・コース外では配置・取得しない。既存の固有スキル解禁条件は維持する。

コースの外側にはスキル回復ゲートを置く。通過すると解禁済み固有スキルの残り待ち時間が最大4秒減る。既に使用可能なら効果は発生しない。車体ごと・ゲートごとに1周1回とし、逆走・往復・復帰による繰り返し回復を防ぐ。

## 初期調整値

| 項目 | 初期値 |
| --- | --- |
| 痕跡の全体上限 | 8個 |
| 痕跡どうしのコース沿い最小間隔 | 40m |
| 痕跡の大きさ | 長さ10m、幅4.5m |
| 寿命 | 60秒、カーブ外側の横位置に応じ最大90秒 |
| 消滅予告 | 最後の8秒で透明化、緩い明滅 |
| 痕跡退出時の加速 | 1.3倍、0.8秒 |
| 同じ痕跡の再取得 | 1周1回、他の痕跡とも1.5秒以上の間隔 |
| 回復ゲート | 各コース3か所、通常ラインより外側 |
| 回復量 | 残り待ち時間を最大4秒短縮 |

コースを横切る別区間でも地面の高さが近い痕跡は近接配置しない。既存ダッシュ板や回復ゲートとの近接配置も抑止する。上限・間隔に達した場合は新規配置を見送り、既存の寿命を延長しない。外側は局所的な曲率から判定し、直線には外側寿命ボーナスを与えない。調整値は `backend/skills/track_effects.js` にまとめる。

これらは初期値であり、逆転性・勝率・最適ラインの分散を保証する測定結果ではない。特に先行者の自分用痕跡への再アクセス、コース長と寿命の関係、後続の実際の利用率をプレイ評価する必要がある。

## 表示と認識

- 既存の橙色の矢印板に対して、痕跡は紫の二本の帯と流れる粒で表示する。「抜けて加速」の短い表示を付ける。
- 回復ゲートは水色のアーチ・床と「↻ スキル回復」で表示する。スキルボタンにも同じ↻を付ける。
- 回復時はゲート位置からスキルボタンへ粒子が飛び、ボタンが光り、残り待ち時間が減る。効果音はSE音量・ミュートに従う。
- 効果終了と表示終了の時刻を揃える。痕跡が寿命切れで消えただけでは退出加速を発動しない。

## CPUと通信

CPUは学習ラインを基準にしながら、近い痕跡・使用待ち中の回復ゲートを目標候補にする。直線重視のCPUは大きく遠回りせず、回復重視の個性はゲートへ寄る。生成・加速・回復のルールはプレイヤーと共通。

マルチプレイではホストが痕跡の配置と寿命を管理し、既存のKART_STATE経路で上限付きsnapshotを配る。ゲストはスキル発動の連番と位置を送り、ホストが一度だけ採用する。非ホストからのsnapshotは採用しない。CPUの発動はホスト側で処理する。各クライアントの自車に対する接触判定と回復は、その車体の既存物理・スキル管理と同じクライアントで行う。

全員が今回の機能に対応すると確認できるまでは、部屋全体で新機能を無効にする。旧版混在時に一部の人だけ痕跡やゲートを利用できる状態を避ける。Workerの変更・再デプロイは不要。

## 検証範囲

- `tests/test_track_effects.mjs`：上限・間隔・非消費・外側寿命・フェード・退出判定・高速通過・逆走/復帰/周回制約・回復量・同期データの検証。
- `tests/track_effects_browser.cjs`：ゲームの固有スキル発動から痕跡生成、退出加速、回復ゲート、HUD粒子、CPUの進路選択、消滅・リスタート時の描画資源解放。
- `tests/multiplayer_devices.mjs`：独立した2ブラウザとローカルWorkerの実WebSocketで、ゲスト発動・ホスト配置・重複防止・共有寿命・期限切れを確認。

ブラウザ上の位置移動や時間短縮を用いる条件は模擬検証として扱い、iPhone/Androidの実機走行・ネットワーク遅延下の公平性・ゲームバランス評価とは区別する。
